# Guarded effect chains

## 1. Agent controls

The official local MCP server exposes 45 tools. `list_effects` pages eight built-in effect types with native parameter units, ranges, defaults, type/enum metadata and tempo-sync flags. There are 54 registered types. `get_effect_chain` copies the full ordered chain and returns an exact `expected_state` token. Omit `target` for master, or pass a stable `track` target. Region targets are refused; regions on a lane share that lane's processing.

`edit_effect_chain` accepts one `action`: `add` with `type_id`; `remove` with `effect_id`; `reorder` with `effect_id` and zero-based `position`; `enable` with `effect_id` and Boolean `enabled`; or `parameter` with `effect_id`, zero-based `parameter` and a native physical `value`. Each request requires the current token, endpoint instance and a unique request ID. Irrelevant fields, nonfinite values, range violations, fractional integer/enum values and read-only meter parameters are refused. There are at most 16 inserts per chain on this surface.

For sync-capable time parameters supply `mode: beats` and positive `beats`; for rates use `mode: beat_rate`. Native value is derived through the existing unit converter using current tempo. Native mode requires `value` and omits `beats`. Preserve decimal identities exactly. Gain is expressed in dB, delay in its published ms/seconds units, and other controls use their catalog units.

## 2. Guarded history and retry

Eight copied complete chain states are retained behind endpoint-lifetime tokens. Comparison covers generation, track identity, effect identities/order/types, enabled state and all active parameter values/modes/beat values. Identical states reuse tokens. Expired or changed states refuse writes. Mixer, note content, dedicated EQ and project tempo are outside this chain-state token; this is not a global project revision.

Each edit reserves independent complete before/after history, prepares an unpublished engine candidate, and captures readback before one publication. Failure leaves the control chain and history unchanged. `undo_effect_chain` and `redo_effect_chain` consume only the matching common effect command at the shared history cursor and restore stable effect IDs. Other native or instrument/note commands at the cursor require their appropriate history owner. A changed chain refuses history without consuming it.

All edits use the existing same-user opt-in write endpoint and immutable 128-receipt ledger. No-ops and refusals also consume receipts. After an uncertain sent request use `request_status` with the same instance and request ID; do not replay with a new identity. Recording, playback, Test and active authoring gestures refuse conflicting writes.

## 3. Processed composition foundation

The common `daw_action_render_composition` API privately renders a selected project range, track or MIDI region through the production bounce pipeline. An isolated region excludes other sources on its lane. Track previews include that lane's regions. Authored mute/solo, gain/pan, automation, inserts and dedicated EQ remain meaningful. Dry mode bypasses inserts and dedicated track/master EQ only in the private clone, retaining source and mixer behavior.

Rendering has one second of preceding context where available, at most ten seconds of requested material, and up to five explicitly requested tail seconds. It rejects invalid ranges/windows, busy authoring and oversized buffers. It retains original level without normalization. Analysis reports peak, RMS, DC and full-scale sample count, a 256-point twenty-ms waveform, 256 whole-range RMS windows and 128 Hann tonal measurements. The spectral window is 2,048 frames starting at an explicit offset into the returned range; short endings are zero padded. These are tonal peak-amplitude measurements, not LUFS or a perceptual preference score.

`analyze_composition` exposes these production renders through MCP. Supply canonical decimal `start_frame`, `end_frame`, optional `tail_frames` and `window_frame`, optional stable track/region target and Boolean `dry`. Omitting the target captures the project mix. The response carries a unique `render_id`, captured insert settings, complete range metadata, original-level metrics and bounded calibrated plots. Analysis changes no authored state, writes no files and consumes no mutation receipt.

`preview_composition` accepts an endpoint instance, fresh request ID and retained `render_id`, and atomically publishes deterministic PCM16 below the private preset library's `CompositionPreviews` directory. It publishes exactly the analyzed audio, even if the project changes or opens another session afterward. Cached audio is immutable; it is not a token authorizing a current-project edit. Four renders and at most 64 MiB of retained samples are allowed; byte pressure can evict before count capacity. An expired token refuses publication. An accepted receipt remains replayable after render eviction. Publication refuses overload above full scale and occupied destinations, and reports directory-sync uncertainty without retrying a possibly published file.

The native instrument Inspect panel now switches between isolated Instrument and actual Region capture (button or M). Region mode measures the first ten seconds at most, plus an explicit one-second tail, through the same production composition action. Dry/Processed toggles bypass private insert/EQ processing while preserving mixer levels. Attack/Sustain/Release select start, midpoint and tail-entry windows. Capture Ref owns independent immutable samples and calibrated plots; Refresh explicitly captures later edits. Save WAV and Save Ref WAV publish the exact retained samples through the common publication action, without implicitly refreshing or normalizing. Closing the inspector or shutting down frees both buffers. Region mode also offers direct finite Listen Capture/Listen Ref/Stop controls over the exact retained samples; playback uses the existing output endpoint and independent PCM ownership.

## 4. Reusable-chain storage foundation

`daw/fx_library.h` and `app/fx_library.c` add a version-one portable chain document under the configured private preset root's `FxChains` directory. Documents contain random preset ID/revision, a display name, ordered stable effect type IDs, enabled states and complete named physical parameters/modes/beat values. Runtime track/effect identities are excluded. Reads create no storage; list views are bounded to 128 entries with invalid-file and overflow diagnostics. Future versions, unknown/missing/duplicated parameters, invalid values and symlink files refuse recall. Cooperating writers use a nonblocking lock; updates require an explicit current revision, preserve one `.previous` document and atomically publish with separate durability readback.

The common portable replacement action reserves complete history, validates every setting, recalculates synced native values for destination tempo, creates fresh independent effect instances and publishes once. Undo restores the entire prior chain with original identities; redo restores the accepted new identities. Identical audible settings are a no-op. Library storage and application are adopted through guarded MCP save/apply and the native effects-panel Chains browser. Existing project serialization embeds complete chain settings and does not depend on this library.

Catalog qualification exposed four preexisting metadata defects. MonoMaker now advertises its actual integer slope parameter. SoftSaturation, Overdrive and Waveshaper expose their complete DSP parameters in the correct order with actual bounds/defaults and the four supported Waveshaper curves. DSP algorithms and project parameter indices are unchanged; parameter metadata at formerly mislabelled positions is corrected.

## 5. Personal chain workflow

The Effects panel's **Chains** button opens the current track or master library. **Save As** stores the captured chain under a new name; **Update** requires a previously saved/recalled preset and its current revision. Neither operation edits the project or consumes project undo. Search filters cached names; **Refresh** reloads files and deliberately captures the current chain. Clicking a row recalls the full chain through one guarded undo step. External changes while the browser is open refuse recall/save until Refresh or reopening. Pointer activation requires a matching release, and clipped controls cannot activate outside the pane.

`list_effect_presets` pages eight metadata entries with ID, revision, label and effect count. `get_effect_preset` returns the complete portable settings, optionally requiring a revision. `save_effect_preset` requires the current exact track/master chain token and a name; omit ID/revision for Save As, or supply both for an explicit update. `apply_effect_preset` requires the current chain token and the selected preset's exact ID/revision. Omit target for master. Recall creates independent runtime effect identities and recalculates synced physical values at destination tempo. Project settings remain complete even after the library files are removed.

## Captured listening integration checkpoint

Region inspection now offers Listen Capture, Listen Ref and Stop Capture in addition to the existing exact Save WAV controls. The output endpoint owns an independent immutable PCM copy, drains normal engine callbacks, then emits captured samples directly without applying effects or normalization again. Playback stops at the captured frame count and zero-pads the last callback. Format mismatch, samples above full scale, nonfinite values, oversized buffers and allocation failure refuse replacement. The buffer remains device-owned until control-path stop/close/replacement; the callback performs no allocation, retirement or locking.

Transport start and MIDI audition cancel finite captured playback. Inspector close/focus loss and project replacement retire it before freeing captures or the old engine. A refresh or comparison mode/window change stops the preceding capture so the displayed analysis remains consistent with playback. Current/reference controls require matched pointer releases; clipped controls refuse activation. Recording/Test/bounce and moving transport refuse listening admission.

The current development checkpoint passes exact callback/device tests, a private paused dummy inspector endpoint, independent current/reference samples, transport cancellation, close-time retirement and project transaction regressions. The actual native input/painter harness also runs an active private SDL dummy output endpoint, starts current/reference playback through input events, observes completion at the exact captured frame count, and verifies Stop/focus cancellation with clean Vulkan validation. The final stable suite and every MCP domain pass. Final-binary App_Run workflows qualify normal save/restart and exact captured audio compatibility. This proves software playback integration; physical output-device quality and human preference remain separate.
