# Nested track groups

Main Edit supports nested, collapsible audio buses. Open **Groups** in the timeline toolbar to create Strings, Woodwinds, Brass, Major Theme or Minor Answer. Select a lane, cycle Parent to a group (or Master), then Apply Parent. Move Up/Down changes sibling order. Existing header rename controls allow other names. Click a group chevron to fold its descendants; expand it to restore their rows. Folded tracks keep playing.

Each child retains its regions, instrument, effects, automation and identity. Its main output flows exclusively into its parent; a group sums its children, processes its own effects/EQ and gain/pan, then feeds its parent or master. Child and group post-fader sends can feed independent returns. Group mute affects descendants; group solo includes descendants and their ancestor buses. A solo child retains its ancestor processing. Group buses cannot contain source regions, instruments or recording inputs. Region/instrument automation stays on source lanes.

Creation, parenting, ordering and folding use guarded common actions and scoped undo/redo. Topology authoring requires stopped transport and no conflicting busy operation. Fold-only changes and their history now work during playback; see [compact track UI](compact_track_ui.md). Folding/order updates preserve DSP state. Reordering changes the visible hierarchy without moving engine track/effect indices. Cyclic parenting and invalid source/return conversion are refused before publication. Returns stay at root and cannot feed groups or other returns.

Session format 26 stores group role, parent references, sibling order, fold state and exact decimal-string persistent identities. Older flat projects load normally. Saved identity survives reopen; runtime generation-bound MCP targets are freshly acquired after project replacement. Complete project settings remain embedded independently of personal library files.

MCP adds `create_group`; `edit_routing` supports group, parent, fold and order operations. `get_routing` includes persistent identity, parent target, depth and visible row (-1 when hidden). Existing effect and routing history tools address group buses. Writes require current instance, exact routing guards and immutable request IDs. Refresh cached MCP discovery for the current 54-tool surface. Group/child labels and base gain/pan now use the guarded [header-control tools](header_mixer.md), with readable mute/solo and shared native history.

Grouped graphs support up to 128 total tracks, four returns and four sends per lane, with existing insert limits. Prepared edge-delay storage is bounded at 128 MiB. Mixing allocates no memory during rendering; child/ancestor/return/master latency is compensated along the graph. Isolated composition capture and stopped live audition retain the relevant ancestor effects.

Verification covers production audio factors, nested latency, folding equivalence, failure rollback, history, saved/reopened IDs and audio, SDK receipts/stale guards, and actual SDL/Vulkan group-manager/header/effects interactions. Native fixtures contain empty instrument lanes and do not edit a song. Supported AddressSanitizer memory-safety checks pass; macOS leak detection was unavailable. Physical interaction and listening acceptance remain separate. Program version stays 0.4.0; this is uncommitted Main Edit development. Collection-scoped native Load/Save is now documented in [collections](project_collections.md).
