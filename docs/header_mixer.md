# Compact track-header mixer

Main Edit provides volume and pan fields for child tracks, group buses and return lanes beside Mute, Solo and FX. Volume is displayed in dB (`V`); pan shows center (`P C`) or left/right percentage. Thin position hints and a focused-field border distinguish these editable fields from command buttons. The existing inspector mirrors accepted header edits so subsequent relative drags start from the current value.

Drag a field vertically: up increases volume or moves pan right; down decreases volume or moves pan left. Hold Shift when beginning a drag for fine movement. Clicking without motion does not jump the value or add undo history. Double-click resets volume to unity (0 dB) or pan to center. After focusing a field, arrow keys change volume by 1 dB or pan by 5%; Shift uses 0.1 dB or 0.5%. Volume spans silence at the bottom, approximately -60 dB above that floor, through +20 dB. Pan spans full left through center to full right. Key repeats are suppressed so one key edge owns one edit.

A complete drag creates one undo entry; reset and keyboard steps each create one entry when they change the value. Cmd/Ctrl-Z and Shift-Cmd/Ctrl-Z use the normal shared history. History owns only the edited scalar and exact project/track lifetime. It leaves the other mixer parameter, instruments, effects, notes and regions untouched, and refuses replay if a later write changed that same scalar. This avoids replacing a complete track snapshot for a small mix edit.

Escape restores the gesture's starting value against its last accepted scalar. Focus loss, resize, scrolling, modal takeover and geometry changes finish the last accepted edit through its undo owner. A deleted/replaced project or track cannot inherit a late drag. Reset presses remain owned until release so sampled pointer input cannot replay them as track-name selection. Header mix edits preserve the current track/region selection and operate during playback through the existing compact mixer publication path. Recording, export and competing authoring/continuous owners retain priority. Keyboard releases continue to the existing audition owner during a header drag, so held notes or pedals can finish normally.

Short projects admit a zero-based timeline view instead of being forced into negative pre-roll; deliberate left scrolling remains available. The timeline now uses a two-pixel gutter at each content edge rather than 24 pixels, reclaiming 44 horizontal pixels. Track rows use subtle variations from the active theme, keyed by persistent identity, with independent selection emphasis; the empty canvas retains its base background. Loop/grid/region drawing stays above the lane fill. Default rows remain 48 pixels with two-pixel gaps. The minimum is now 36 pixels so the name, five controls and meter remain available together. Header width stays consistent when groups fold or expand. No new saved-layout fields, session schema or program version change is required.

Verification covers independent child/group gain and stereo factors, scalar undo/redo with unrelated pan and MIDI preserved, invalid/stale writes, no-op clicks, fine keyboard steps, reset/escape isolation, focus/resize/project guards, live playback updates, matching inspector values and save/reopen audio. Native Vulkan captures cover normal and minimum-height controls with lane backgrounds; the stable/headless suite covers the wider application. These are software checks; physical mouse/trackpad/listening acceptance follows in the refreshed Desktop Main Edit package.

## Guarded MCP controls

`get_track_controls` reads the name, linear base gain, stereo pan, mute/solo and group/return roles for a generation-bound stable track handle from `get_routing` or project inspection. It returns persistent identity and `expected_state`. `set_track_control` writes exactly one `control` (`name`, `gain`, or `pan`) with `value`. `undo_track_control` and `redo_track_control` require the same target and field at the shared history cursor; they cannot skip another domain command.

Gain writes use linear amplitude 0–10: 0 is silence, 1 is unity, and 10 is +20 dB. Pan is stereo balance -1 left, 0 center, +1 right. Names preserve 1–127 UTF-8 bytes with no control characters. Mute/solo are inspection fields only. Group and return buses use the same base controls as source children. This adds no track-wide automation.

Supply the current instance, fresh immutable request ID and read token. Sixteen copied states are retained; stale target lifetimes, expired tokens or a changed addressed field refuse the edit. Unrelated fields may change independently and are preserved by both edits and history. Writes and scoped history allow playback; recording, continuous gestures, project/text owners and exports retain priority. Recover uncertain outcomes using `request_status` with the original instance/ID before deliberate retry. Reacquire runtime handles after project replacement; persistent IDs and labels survive native session Save/Load.

Native header renaming now shares the guarded/reserved common label action with MCP; it reserves undo history before changing a name and replay resolves stable identity rather than an array index.
