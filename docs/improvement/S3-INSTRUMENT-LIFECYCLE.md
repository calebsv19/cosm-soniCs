# S3.6 — Existing instrument gates, release, and sound quality

## 1. Implemented behavior

1. MIDI note duration is the held gate. Attack/decay/sustain runs during that gate; release begins at its end and decays from the envelope's actual gate-end level, including early note-off during attack or decay. Zero release ends immediately. The authored MIDI region remains a hard render boundary: release may continue beyond a note inside the region, but this slice does not automatically lengthen a region or add export tails.
2. Live audition note-off ends the gate and retains its release voice; an on/off pair at the same render boundary uses the existing minimum one-sample note duration. A repeated held pitch releases the earlier voice and starts a new one. At most 256 audition descriptors are prepared during engine creation in both the note list and renderer. At capacity the oldest released descriptor is reclaimed; held pitches are not selected for that reclamation. Updates, release retirement, and panic reuse storage without heap calls in the instrumented paths.
3. Target-track, preset, or instrument-parameter changes start a fresh audition voice set, avoiding old voices being reinterpreted with a different global instrument configuration. Track remapping still uses prepared runtime identities. All-notes-off is a hard voice panic, not musical note release. While playback continues, existing project effects may still contain their tails.
4. Released voices retire at worker boundaries when their envelope ends. After the last stopped release, the existing track/master path receives silence for at most two additional seconds, fading the final 5 ms to zero. The worker then returns to idle without flushing already queued release audio. Drain completion clears stale DSP history without flushing the queue; a fresh idle audition also resets history. This is a bounded audition-tail policy, not an unlimited reverberation-tail detector.
5. Play-from-idle, stop/pause, seek, loop-configuration changes, and ordinary loop wraps explicitly clear live audition voices. This prevents absolute-time audition gates from becoming stranded across transport changes. Ordinary wraps still preserve authored source-control ramps and project effect histories. Stopped audition advances its own offset while the project transport stays fixed.
6. Existing instrument volume and pan automation lanes now affect output, alongside existing instrument-parameter lanes. Clip and track normalized deltas combine; volume uses `clamp(1 + delta, 0, 2)`, and pan uses the existing stereo balance law with a clamped -1..1 value. Mono ignores balance; channels beyond the first two retain unity balance. The existing polyphony clamp remains before this signal gain.
7. Saw-based components use a sample-rate-aware polynomial discontinuity correction. Triangle components sum only representable odd harmonics, capped at harmonic 63 for bounded work. Explicit sine partials at or above Nyquist are omitted. Existing preset identity, parameters, and nonlinear shaping remain. Nonlinear waveshaping, modulation, and final polyphony clipping can still produce aliases; this is a measured improvement to existing waveforms, not fully band-limited synthesis or oversampling.

## 2. Acceptance

`test-instrument-lifecycle` covers early gate release during attack/decay/sustain at 44.1/48/96 kHz, exact release completion, reset/partition determinism, stereo agreement, an independently measured folded saw component, combined track/clip volume and pan lanes, retrigger/256-voice bounds, stopped and playing retirement, target/preset changes, panic, zero guarded heap calls, and actual dummy-device worker return to idle. `test-midi-instrument-render` retains region, preset, parameter, automation, stopped audition, and bounce integration coverage with explicit audible-release and post-release-silence assertions. Both are in `test-stable`.

The coherent 7 kHz saw fixture at 48 kHz measures the folded 20 kHz component dropping from approximately 0.15631458 to 0.04420133 amplitude. The triangle fixture has no measurable component at that tested folded frequency under its assertion tolerance. This does not measure every preset, pitch, modulation, or nonlinear stage.

Final commands, source fingerprints, sanitizer coverage, and limits are in [the S3.6 receipt](evidence/s3-instrument-lifecycle.json). Dummy-device success is software scheduling/lifecycle evidence; no physical keyboard/device, listening, or subjective preset approval is claimed.

## 3. Remaining boundaries

No new instrument family, external MIDI routing, per-note expression, arbitrary preset layering, voice-stealing UI, or export architecture was added. Full-file bounce remains the pre-S3.7 architecture. Sustained maximum-polyphony CPU qualification belongs to S4; a fixed descriptor/harmonic bound is not a guarantee that every maximum workload meets an audio deadline.
